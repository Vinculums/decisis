# Threat model

The sandbox exists to keep two things apart: durable knowledge that a team relies on, and the
working material of one task (outside data, intermediate paths, unapproved claims). This page says what
the code does to keep them apart and what it does not do. Each "protects" item names the code or the
test that shows it.

## What it protects

**A private working directory.** Each task gets a new directory `decisis-<random hex>` created with
mode 0700, so other users on the machine cannot list or open it. It is under `/dev/shm` (memory-backed
tmpfs) when that directory exists and is writable, otherwise under the system temporary directory.
(`Sandbox.__init__` in `src/decisis/sandbox.py`; `test_the_task_file_lives_in_its_own_private_directory_and_is_gone_after`.)

**Read-only reasoning.** The graph is written once, by one connection that closes before any query.
Every query opens its own connection with `read_only=True`, and Relate refuses a write on it with
`WriteOnReadOnly`. A query, whether written by a person or generated by an agent, cannot change the
task graph, and it never reaches Vinc: the sandbox has no connection to Vinc at all.
(`Sandbox.query`; `test_reasoning_reads_cannot_write`.)

**A single writer.** While the writer connection is open, Relate's file lock refuses a second writer and
any reader (`storage locked`), so nothing can read a half-loaded graph or write beside the loader. A
sandbox is loaded once; a second load is refused. (`test_an_open_writer_locks_out_both_a_second_writer_and_a_reader`,
`test_a_sandbox_is_loaded_once`.)

**A load that matches the snapshot.** After loading, the node and edge counts are compared with the
snapshot; a repeated id or an edge with a missing endpoint stops the run and is named.
(`test_an_edge_with_a_missing_endpoint_fails_the_load_by_name`, `test_a_repeated_node_id_fails_the_load_by_name`.)

**No injection through the snapshot.** Node kinds and edge types become labels only after every
non-alphanumeric character becomes `_` and the result starts with a letter; values go in as query
parameters; hop and result bounds are substituted as integers (`paths --hops` 1 to 6, `paths --limit`
1 to 100, `impact --hops` 0 to 6). (`_label`; `test_a_label_that_could_inject_cypher_is_refused`,
`test_paths_bounds_hops_and_limit_with_an_argparse_error`.)

The schema in the MCP `query` tool's description is built from the snapshot, so it is data an agent
reads. It is bounded and escaped: a label, edge type or property key is shown as is only when it is a
plain ASCII identifier, in backticks when it is printable and at most 64 characters, and otherwise left
out with a count; the label and edge sections stop at 4,096 bytes; the example node id is a Cypher string
literal with quotes, backslashes, line breaks and every character outside printable ASCII escaped, and
ids over 128 characters are not used. No text from the snapshot starts a line of its own, and the
description says the names are data, not instructions. (`cypher.describe`;
`test_snapshot_names_and_ids_reach_the_description_escaped_and_bounded`,
`test_a_non_ascii_kind_is_backticked_and_every_example_passes_the_check_and_runs`.)

**Bounded tool replies.** Every MCP reply, text and structured content together as the server
serializes them, stays under 1 MiB: the longest list is shortened from its end until the reply fits,
and a `cut` note names each shortened list. (`compact.fit`, `serve.sent_size`;
`test_what_the_server_sends_stays_under_the_byte_cap`.)

**Deletion.** The directory is removed when the command ends, in a `finally`, so a failed task removes
it too. The demo prints whether the removal happened and the tests assert the scratch root is empty.

**Cleanup after a kill.** Each task directory holds `owner.json` with the process id, the process start
time (Linux) and the host name, and so does the parent directory of an MCP server. A new sandbox, a new
server and `decisis gc` remove a `decisis-<32 hex>` or `decisis-serve-<32 hex>` directory under the same root only when it is a real directory owned by the current user, older than 10 minutes,
and its owner process is gone (on Linux, a reused process id is told apart by its start time). A live
owner, another user's directory, a `decisis-*` entry that is a symbolic link, a directory under another
root and a directory without a readable owner record (or with a process id outside 1 to 2^31 - 1) are left
alone, and removal never follows a symbolic link inside the root. A root that is itself a symbolic link is
followed and used as the root. An error on one entry keeps that entry and the sweep goes on; the sweep a
new sandbox runs never stops the command, and `decisis gc` names each entry it kept because of an error.
(`sweep` in `src/decisis/sandbox.py`; the cleanup tests in `tests/test_sandbox_limits.py`.)

**Size and time limits.** A graph over 50,000 nodes or 250,000 edges is refused before the database is
opened. Every query runs in a separate query process and is stopped after 60 seconds by killing that
process; the task directory is still removed and the command exits with 1. The caps and the time limit
can be raised with `--max-nodes`, `--max-edges` and `--query-timeout` or the `DECISIS_MAX_NODES`,
`DECISIS_MAX_EDGES` and `DECISIS_QUERY_TIMEOUT` environment variables, but not past 1,000,000 nodes,
5,000,000 edges and 3,600 seconds. `audit --depth` is 1 to 16. (`Limits`, `check_size` and `_Worker`;
`test_a_graph_over_the_node_or_edge_cap_is_refused_before_anything_is_written`,
`test_a_query_over_the_time_limit_is_stopped_and_the_directory_is_removed`,
`test_audit_depth_is_bounded_like_paths_hops`.)

**An approval digest before any write.** `propose` writes nothing. It prints the exact write set with a
digest: the first 16 hex digits of SHA-256 over the space, nodes and edges. `commit` recomputes the
digest from the plan file and refuses unless it equals both the plan's digest and the one given with
`--approve`, so a plan edited after approval is refused. Only `affected` findings enter a write set.
(`check_approval` in `src/decisis/commit.py`; `test_nothing_is_written_without_the_matching_approval_or_after_the_plan_changed`,
`test_unverified_findings_are_held_back`.)

**Create-only writes and read-back.** `commit` skips ids that already exist and writes the rest with
`create_only` and an operation id derived from the digest, so a repeated commit adds nothing. It then
reads every new node back and compares each property, and checks out each record again to confirm each
edge with its type and direction. Any difference makes the exit code non-zero.
(`test_an_approved_write_is_read_back_and_existing_ids_are_left_alone`, `test_a_store_that_kept_something_else_fails_the_read_back`,
`test_an_edge_stored_the_wrong_way_round_fails_the_read_back`.)

**Least-privilege keys.** `checkout` needs only a read-only key; only `commit` asks for a full key. The
key comes from `VINC_API_KEY` and is not written to any file the tool produces.

**Provenance on outside data.** Each package and advisory keeps where it came from and when it was read;
each advisory keeps its source URL and a SHA-256 of the record that was read, and each written record
carries them. `--osv-cache` replays a saved set of advisories and refuses the network.

**Outbound requests to OSV.** `audit` and `propose` send OSV queries to `https://api.osv.dev`. When the
inventory has GitHub Actions packages they also download, once per run, OSV's export of GitHub Actions
records from `https://osv-vulnerabilities.storage.googleapis.com/GitHub%20Actions/all.zip`, run by the
same OSV project, to learn the spelling OSV stores for each action name. The download is cut off at
64 MiB, and the archive at 100,000 records of 4 MiB each; only package names are kept from it. With
`--osv-cache` neither host is asked.

**Outbound requests to GitHub.** `init --github` sends only GET requests, only to `https://api.github.com`
on port 443: a `Link` header, a redirect or a final answer that points anywhere else is refused before
anything is sent there or read from it. `GITHUB_TOKEN` is read from the environment, never from a flag, and
goes only in the `Authorization` header; a token with a space, a line break or a character outside
printable ASCII is refused without echoing it, and every error message has the token replaced by `[token]`.
The token is not written to the snapshot or printed, and the `repr()` of the client and of the bound reader
leaves it out. A broken answer ends in the same one-line error and exit code 1 as a network error. Answers over 20 MB are refused, and the listing stops at
`--limit` (at most 5,000) closed pull requests. (`src/decisis/github.py`;
`test_it_sends_only_get_requests_to_api_github_com_and_follows_link_headers`,
`test_a_next_page_or_an_answer_on_another_host_is_refused`, `test_a_redirect_to_another_host_is_not_followed`,
`test_the_token_goes_only_in_the_authorization_header_and_never_into_an_error`, `test_init_never_prints_the_token`,
`test_the_repr_of_the_client_and_the_bound_reader_never_holds_the_token`,
`test_a_broken_answer_fails_the_command_with_a_message_and_no_traceback`.)

**A read-only MCP server.** `decisis serve --mcp` lists only `impact`, `paths`, `audit`, `check` and `query`, and refuses
any other tool name and any argument its schema does not list. Bounds are checked before a sandbox is
built; a code path with `..`, an absolute path or another repository's prefix is refused. `check` refuses a
changed path with `..`, an absolute path, a backslash or a control character, or one that resolves outside
`--root`, and a `base` that starts with `-` or holds whitespace or a control character before git runs; git
runs through the hardened helper and timeout of `check --base`. A snapshot file that changes and fails to
load leaves the previous snapshot in use, and the reply says so. `audit` reads a
lockfile only when its resolved path, after symlinks, lies under `--root`, and uses the network only with
`--allow-network` and no `--osv-cache`. Each call builds and deletes its own sandbox inside one private
`decisis-serve-<32 hex>` directory, which the server removes on SIGTERM, SIGINT or the end of stdin, even while a
call is still running; that directory records its owner like a task directory, so after a SIGKILL the
cleanup above removes it with the sandboxes inside. (`src/decisis/serve.py`; `test_a_write_shaped_request_is_refused_and_nothing_is_written`,
`test_a_server_stopped_during_a_slow_call_leaves_no_sandbox`,
`test_gc_removes_the_directory_of_a_server_killed_with_sigkill_and_keeps_a_live_one`,
`test_the_audit_reads_only_under_the_root_and_refuses_an_escaping_symlink`, `test_the_audit_uses_the_network_only_when_allowed`,
`test_check_refuses_a_path_outside_the_root_and_a_base_that_could_pass_for_an_option_before_git_runs`,
`test_check_over_mcp_with_base_runs_git_through_the_hardened_helper_and_matches_the_cli`,
`test_a_snapshot_that_fails_to_reload_leaves_the_previous_one_and_the_reply_says_why`.)

**A read-only `query`.** The `query` command and tool refuse a write three ways, and each is tested without
the others. The text check refuses `CREATE`, `MERGE`, `SET`, `DELETE`, `REMOVE`, `FOREACH`, `LOAD CSV`,
`DROP`, `SHOW`, `USE` and the other admin clauses in any case, after comments and inside subqueries, refuses
`CALL { }` subqueries and every procedure but the schema ones, and allows one statement only. The query
process plans the statement with `EXPLAIN` on a read-only connection and runs it only when Relate plans it
as a read. The read-only connection refuses a write on its own. Rows stop at 500 and 1 MiB, and the query
runs under the same time limit as every other query. (`src/decisis/cypher.py`;
`test_the_check_refuses_every_write_load_and_admin_form_before_running`,
`test_without_the_check_the_query_process_refuses_a_write_from_relates_plan`,
`test_the_read_only_connection_refuses_a_write_on_its_own`, `test_rows_stop_at_the_row_cap_with_a_note`,
`test_a_query_past_the_time_limit_is_stopped`.)

**`check` never runs repository code.** Imports are read with `ast` for Python and a scanner for JavaScript
and TypeScript; no module of the repository is imported and no build or package manager runs. `--base`
runs `git diff --name-only` with the repository's hooks, fsmonitor and pager turned off, and refuses a ref
that looks like an option. A changed path outside the repository is refused, and a file reached through a
symbolic link that leads outside it is `unresolved`. (`src/decisis/check.py`, `src/decisis/imports.py`;
`test_repository_code_is_parsed_and_never_run`, `test_base_ignores_the_repositorys_own_hooks_and_fsmonitor`,
`test_base_refuses_a_ref_that_looks_like_an_option`, `test_a_changed_path_outside_the_repository_is_refused`,
`test_a_symbolic_link_out_of_the_repository_is_unresolved`.)

**The GitHub Action.** The workflow asks for `contents: read` and `pull-requests: write` only. Inputs reach
Python as environment variables, never through `${{ }}` inside a shell script, and Python runs with `-I`,
so a module in the pull request's checkout cannot shadow decisis. Third-party actions in `action.yml` are
pinned to commits. The base commit must be a SHA from the event payload. Every title, path and reason in
the comment is escaped and mentions are broken, so a decision title cannot inject Markdown or notify
anyone. Only the bot's own marked comment is updated; a marked comment by anyone else is left alone. On a
fork the result goes to the job summary. (`src/decisis/action.py`, `action.yml`;
`test_a_hostile_title_and_path_reach_the_comment_only_as_escaped_text`,
`test_third_party_actions_are_pinned_and_no_expression_reaches_a_shell`,
`test_the_action_has_its_inputs_and_the_workflow_asks_for_the_least_permission`,
`test_the_base_must_be_a_commit_sha_from_the_payload`, `test_the_bots_marked_comment_is_found_across_pages_and_updated`,
`test_a_fork_pull_request_writes_only_the_job_summary`.)

## What it does not protect

- **Erasure.** Deleting a file is not secure erasure. tmpfs can be swapped to disk, and where `/dev/shm`
  is missing (macOS, Windows) the directory is on the disk under the system temporary directory. Data
  that must not touch a disk needs encrypted scratch storage with key destruction, which is not built.
- **A crash or kill, until the next run.** A process killed with SIGKILL, or a machine that loses power,
  skips the `finally` and leaves the directory behind (for `decisis serve`, its `decisis-serve-*` parent
  with any sandbox inside) until the next sandbox, the next server or `decisis gc` under the same root
  removes it, at least 10 minutes later. On Windows nothing removes it; delete it by hand. A
  directory left by decisis 0.1.1 or earlier has no owner record and is never removed automatically.
- **The same user and root.** 0700 keeps out other users, not other processes of the same user or an
  administrator.
- **A root that changes under the server.** `serve --mcp` resolves a lockfile path, checks it is under
  `--root`, then reads it. A process that can write under `--root` can swap a file for a symlink between
  the check and the read. Give the server a root that only you write to.
- **What GitHub says.** `init --github` trusts GitHub's answers for titles, descriptions, reviews and file
  names; anyone who can edit a pull request's description can change its `statement` until the next
  `init`. The content hash records what was read; it does not authenticate it. Give `GITHUB_TOKEN` read-only
  access to the one repository (a fine-grained token with pull request read access) rather than a broad
  classic token: decisis never writes to GitHub, so it needs nothing more.
- **Files you ask for.** The snapshot from `checkout`, the report from `audit --out` and the plan from
  `propose` are written where `--out` says, on whatever disk that is, and are never deleted by the tool.
  A snapshot of a private space is private data; keep it out of public repositories (the root
  `snapshot.json`, `report.json` and `plan.json` are ignored by git). The demo's `demo/sample.rl` is kept
  on purpose and holds synthetic data only.
- **Who approves.** The digest binds an approval to one write set; it is not a secret or a signature.
  Anyone who can read the plan can compute it. The rule that only a person supplies it is procedural
  (the skill tells the agent to stop and show the write set); the full key is the real authority.
- **Whether a finding is true.** The audit checks versions against the advisory's ranges and the
  decision's rule, but OSV data can be wrong or late. A content hash records what was read; it does not
  authenticate OSV. Before the digest is shown, `propose` and the demo check each record against a graph
  rebuilt from the snapshot, the lockfile and OSV: the advisory's content hash and severity equal the OSV
  record's; each version is a package of that name in the lockfile, inside the advisory's ranges, and
  reached by one of the record's paths; each path runs from the repository to the record's own package and
  advisory and exists in the graph; the development flags along each path match the record's scope; and
  each `relates_to` target is a decision in the snapshot. A record that fails is held back. This catches a
  report edited in those fields; it does not check the statement text, the verdict wording, or whether OSV
  itself is right.
- **Text in outside data.** Advisory summaries and lockfile fields are stored as data and never run as
  queries, but an agent that reads them can still be misled by what they say.
- **YAML alias bombs.** pnpm and Yarn Berry lockfiles are parsed only after a scan of their YAML events
  refuses any anchor or alias, nesting deeper than 64 levels, and input over 64 MiB, so a few hundred bytes
  cannot expand into gigabytes. (`src/decisis/yamltext.py`;
  `test_a_lockfile_with_a_yaml_anchor_is_refused_before_anything_expands`.)
- **Memory and disk.** The caps bound the number of nodes and edges, not the size of their properties,
  and a query can use a lot of memory before its time limit; there is no memory limit on the query
  process. Loading is not under the time limit; the size caps bound it.
- **A pull request that changes the snapshot.** The action reads the snapshot, the inventory and the
  rules from the pull request's own checkout, so a pull request can edit a decision or drop a rule and the
  comment judges the edited version. Keep the snapshot path under CODEOWNERS review, or read it from the
  base branch in an earlier step.
- **The endpoint.** The key is sent to the Vinc MCP URL, which `VINC_MCP_URL` can change. Point it only
  at a server you trust.
- **The fake Vinc.** The demo's in-process Vinc imitates the calls the tool makes; it is not a security
  boundary and says nothing about the real server's access control.
